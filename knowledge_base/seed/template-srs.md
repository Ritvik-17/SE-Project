# SRS template

1. Introduction: purpose, scope, product overview, definitions (link to the glossary), references (regulations and policies by version).
2. Stakeholders and sources: each stakeholder role and each input source with its sensitivity classification.
3. Functional requirements: grouped by capability; each with ID, statement, priority, categories, source, acceptance criteria.
4. Non-functional requirements: performance, availability, security, privacy, usability, data, integration, audit, operational; each measurable.
5. Use cases and user stories.
6. Compliance mapping: requirement to regulation/policy clause with evidence and review status.
7. Risks: register with likelihood, impact, mitigation and linked requirements.
8. SDLC: selected model, justification, tailored workflow, gates and approvers.
9. Assumptions, dependencies, open issues.
10. Approvals: who approved the baseline, in which role, when.
